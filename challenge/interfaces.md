# Mock Interfaces

All interfaces below are mocked for the PoC. Each mock implements the exact same contract
as the real system would. Swapping a mock for a real adapter is a configuration change, not a code change.
Write operations return `status: "recorded"` and log to `challenge/data/mock_writes.log` — nothing touches a real system.

---

## policy_store

Stands in for: a company SharePoint / knowledge base / RAG-indexed document store.

```
list_policies() → [{ doc_id: string, title: string }]
get_policy(doc_id: string) → { doc_id: string, title: string, text: string }
```

**Mock behaviour:** Reads from `challenge/data/policies/` directory. Each `.txt` file is one policy doc.
**Real behaviour:** Queries a vector store or SharePoint API with the same response shape.

---

## email_connector

Stands in for: company email system (Exchange / Gmail / Outlook API).

```
send_draft(to: string, subject: string, body: string) → { draft_id: string, status: "recorded" }
```

**Mock behaviour:** Appends the draft to `challenge/data/mock_writes.log` with timestamp. Does not send.
**Real behaviour:** Calls Exchange/Gmail API with the same arguments. `draft_id` comes from the mail system.

---

## crm_connector

Stands in for: CRM or ticketing system (Salesforce Service Cloud, Zendesk, Freshdesk, etc.).

```
get_complaint(complaint_id: string) → { complaint_id, rep_id, channel, severity, complaint_text, status }
log_complaint(complaint_id: string, agent_response: string, resolution_type: string) → { ticket_id: string, status: "recorded" }
update_status(complaint_id: string, new_status: string) → { complaint_id, new_status, status: "recorded" }
```

**Mock behaviour:** `get_complaint` reads from `challenge/data/complaints.json`. Write operations append to `challenge/data/mock_writes.log`.
**Real behaviour:** Calls CRM REST API with the same arguments.

---

## Notes

- Every mock write is idempotent for the demo: running the same case twice produces the same log entry, not a duplicate ticket.
- The manifest at `challenge/data/manifest.json` (generated by synth.py) is the answer key for planted demo cases.
- Real company data must never be placed in `challenge/data/`. All rows are synthetic.
